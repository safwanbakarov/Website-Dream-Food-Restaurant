# Handover Summary

## Purpose

This repository has been prepared so another AI/developer can continue the Dream Food Restaurant website without needing the original chat history.

## What is already decided

- The project is pro bono.
- MVP hosting must cost **RM0**.
- The site should be mobile-first and static-first.
- Preferred deployment target: **Cloudflare Pages**.
- Design direction: **Modern Souq**.
- Ordering/contact should route to existing external channels where possible.
- The public repository must not contain the confidential strategy whitepaper.
- Missing business facts must be marked as unresolved, not guessed.

## What is NOT complete

- Production website code
- Final menu verification
- Final opening hours verification
- Final phone/WhatsApp verification
- GrabFood link verification
- Reservation process approval
- Halal certification wording verification
- Final restaurant photography/assets
- QA
- Production deployment

## Handover sequence

1. Read `docs/PROJECT_BRIEF.md`.
2. Read `docs/AI_HANDOFF.md`.
3. Review `docs/MENU_REFERENCE.md`.
4. Read `docs/ARCHITECTURE.md`.
5. Check all unresolved items in `STATUS.md`.
6. Build the static MVP.
7. Keep unresolved facts as placeholders.
8. Update `STATUS.md` after each completed phase.
9. Do not mark the project live until all launch blockers are cleared.

## Definition of a successful handover

The next builder should be able to:
- understand the objective,
- see which sources are authoritative,
- know what not to invent,
- know which architecture to use,
- know what remains unresolved,
- and continue coding without needing the original planning conversation.
